# S4 — On the phone: auth, PWA, notifications

Goal: Cockpit runs online, installs on a phone and sends the right notifications at the right time. This slice produces **code and documentation**; the owner performs the deployment. Depends on S2 (capture endpoint) and S3 (block check-ins). Product rules: [SPEC.md](../SPEC.md) (interface and growth).

## 1. Production database
- Switch from `drizzle-kit push` to versioned migrations for production: `drizzle-kit generate` into `drizzle/`, a `npm run db:migrate` script that applies them to `DATABASE_URL` (libSQL file or Turso with `DATABASE_AUTH_TOKEN`). `db:push` stays for local development. A CI job applies the migrations to an empty database to prove they run.

## 2. Authentication (single user, passkey)
- WebAuthn with `@simplewebauthn/server` and `@simplewebauthn/browser`. Tables: `credentials` (id, public key, counter, transports, created at, label), `sessions` (hash, expiry).
- Enrollment is possible only while no credential exists **and** the request carries the one-time `COCKPIT_SETUP_TOKEN` env value; afterwards `/connexion` offers login only. A second device is added from Réglages while logged in.
- Signed, HTTP-only, `SameSite=Lax`, `Secure` cookie using `COCKPIT_SESSION_SECRET`. 30-day sliding expiry.
- Protect **every** page, server action and API route with the Next 16 proxy file (read `node_modules/next/dist/docs/01-app/01-getting-started/16-proxy.md` first) and re-check the session inside each server action (the docs warn that actions are reachable by direct POST). Machine endpoints use bearer tokens instead: `/api/sync` and `/api/cron/tick` (`COCKPIT_CRON_TOKEN`), `/api/capture` (`COCKPIT_CAPTURE_TOKEN`).
- Demo mode (`COCKPIT_DEMO=1`) bypasses auth. Unit-test the session and token helpers; test with `curl` that protected routes return 401/redirect without a session.

## 3. PWA
- `app/manifest.ts` (name Cockpit, `lang: fr`, standalone, dark theme and background colours from the tokens), icons generated as SVG/PNG from a simple compass mark in the notebook palette, `apple-touch-icon`.
- A service worker for an offline shell: cache the app shell and the last rendered Aujourd'hui for read-only offline viewing, show a clear "hors ligne" banner, never cache authenticated API responses. Keep it small and hand-written.
- Phone navigation: bottom tab bar items become Jour, Tâches, + (capture), Objectifs (placeholder route until S6, hidden until it exists), Plus. Keep the tab bar working with safe-area insets.

## 4. Push notifications
- Web Push with `web-push` and VAPID keys (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`). Table `push_subscriptions`. A "Notifications" section in Réglages: enable on this device, send a test, list devices, remove one.
- `/api/cron/tick` (bearer `COCKPIT_CRON_TOKEN`) runs every 5 minutes: sync, then compute due notifications with a pure, unit-tested function `dueNotifications(now, state, settings)` and send them once each (table `notifications_sent` keyed by kind and date). Kinds: block-end check-in (only when the linked task is still open), 22:45 clôture, 23:00 écrans off, morning cap (07:30 weekdays, 09:30 weekends, times in settings), deadline at risk (an Urgent or Haute task with no block before its due date). Notification clicks deep-link to the right screen.
- Scheduling: the free hosting plan limits cron frequency, so add `.github/workflows/cron.yml` with `schedule: "*/5 * * * *"` calling `$COCKPIT_URL/api/cron/tick` with the bearer token from repository secrets (`COCKPIT_URL`, `COCKPIT_CRON_TOKEN`). The workflow must fail visibly when the call fails.

## 5. Deployment guide
- `docs/DEPLOY.md`: exact steps for the owner: create the Turso database and token, import the repository on Vercel, set every environment variable (list them all with where each comes from), run the migrations, enroll the passkey with the setup token, install the PWA on iPhone, add the GitHub secrets for the cron, and add the iOS Shortcut that posts to `/api/capture`. Include a troubleshooting section.
- `.env.example` lists every new variable with a comment.

## Done when
- Locally with auth enabled (`COCKPIT_DEMO` unset, a throwaway database): enrollment with the setup token works up to the point a real authenticator is needed (cover the server logic with tests), protected routes reject anonymous requests, tick sends nothing twice (unit tests), the manifest and service worker are served and the app passes an installability check you can run headless.
- Demo mode behaves as before. `npm run check` passes.
