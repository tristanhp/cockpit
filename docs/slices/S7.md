# S7 — La revue and the week engine

Goal: the Sunday review runs in the app in ten minutes and ends with a week you confirm. Depends on S3 (blocks, engine) and S6 (goals). Product rules: [SPEC.md](../SPEC.md) (the four moments, priority and effort).

## 1. Data
- `reviews`: id, kind (`weekly` for now), `weekStart`, `status` (`draft` | `done`), `data` (json: numbers, win, focus per priority project, adjustments), `createdAt`, `completedAt`. A review is saved as a draft at every step so an unfinished one can be resumed in one click.
- `weekly_metrics`: week start, effort points done, points planned, blocks kept and planned, rituals done, sport sessions done and planned (from the `socle` calendar), computed by a pure function and recomputed on sync.
- Settings: review day and time (default Sunday 19:30), minimum point budget.

## 2. Budget and velocity (pure, unit-tested)
- `velocity(weeks)`: median of effort points done over the last four complete weeks. `budget = max(min, velocity)`.
- `load(plan, budget)`: ratio and a message when overcommitted; shown before the week is proposed and on Aujourd'hui when the week is over budget.

## 3. The week engine (`src/engine/week.ts`, pure, unit-tested)
- `proposeWeek(weekStart, tasks, goals, slots, budget, options)`: fills the week in priority order (Urgent, Haute, Moyenne, Basse) within the point budget, using S3's `placeTask`. Protected slots and habits stay untouched; avoided events need approval. Reserve one block for each drifting goal (*sans fil*) unless it is paused. Return the proposal as a list of blocks plus what did not fit and why, with Maintenance-type (Basse) work dropped first when overloaded.
- Writing a confirmed proposal uses S3's calendar write; nothing is written before confirmation.

## 4. The revue (`/revue`)
Five steps, saved as you go, each prefilled. Pure helpers compute the data.
1. **Une page**: sport done against planned, blocks kept, tasks done, last week's focus held or not, and the **jamais deux fois de suite** alerts (missed revue or clôture, sport below plan, sleep target missed, under 60 % of blocks kept), each only when it occurred in two consecutive weeks. Quiet wording, one question: "qu'est-ce qui te permettrait de reprendre ?".
2. **Tes chiffres**: four small fields: average sleep, bedtimes on target, energy out of 5, one win.
3. **Les fils**: each active goal with progress and signal; a *sans fil* goal asks one question: plan something or pause it.
4. **Le focus**: one result per top-priority project, prefilled from next actions; editable.
5. **Proposer la semaine**: budget, load, then the proposed blocks as a table grouped by day with the reason per block; confirm all, or adjust and confirm.
A *draft* revue is prepared automatically at the configured time by the S4 tick (when S4 is deployed) or on first open.

## 5. Storage and mirrors
- Cockpit is the source of truth. After completion, mirror to the Notion reviews data source when a source with role `reviews` is enabled, through a connector `push` using a field mapping in the source config (`reviewMap`: which Notion property receives which review field). No property names in code.
- Export a Markdown summary to `VAULT_REVIEWS_PATH` when set, one file per week.
- Extend the existing `/semaine` (from S3) into the real planning view: the week as columns, blocks by day, the point budget bar, drag-free (buttons) move of a block to another proposed slot.

## Done when
- In demo mode: the five steps run end to end and save a review; the alerts fire on constructed history in unit tests and in the demo data; the proposed week respects protected slots, Sunday, the work window and the budget; confirming creates the blocks.
- `npm run check` passes.
