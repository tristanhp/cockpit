# S6 — Vision, goals and threads

Goal: every goal has a thread down to today's work, and anything without a thread is visible. Depends on S2 (can run after S5 so habits exist). Product rules: [SPEC.md](../SPEC.md) (goals and habits).

## 1. Data (all data-driven)
- `vision`: identity statements (list), a 3–5 year horizon text, the rules of the system (list), editable in the app.
- `years`: id, theme name, motto, start and end. `seasons` already exists.
- `goals`: id, title, `horizon` (`year` | `season`), `yearId`, `seasonId`, `parentGoalId` (a season goal can serve a year goal), `pillarId`, `measure` (`milestones` | `number` | `habit` | `boolean`), `target`, `current`, `unit`, `status` (`active` | `paused` | `done`), `dueDate`, `notes`.
- `goal_links`: goal id, kind (`project` | `milestone` | `habit` | `task`), ref id.
- Seed from `config/seed.*.json` (optional `vision`, `years`, `goals`); the demo database has a generic example set.

## 2. Rules and signals (pure, `src/engine/goals.ts`, unit-tested)
- **At most 3 active goals per season**, enforced on the server and explained in the UI ("pause one to add another").
- `progress(goal)`: milestones reached over planned; number current over target; habit weekly percentage against target; boolean done or not.
- `thread(goal)`: the chain goal → projects → milestones → tasks → blocks, following `goal_links` and project membership.
- Signals: **sans fil** (an active goal with no task or block planned in the next 14 days), **à l'arrêt** (a linked project with no next action, or one older than 7 days), **orpheline** (a task with no project), **sur le fil** (work this week and milestones on time). Every priority project must link to a goal or be marked "hors objectifs" on purpose.

## 3. UI
- `/objectifs`: the vision block, the year with its theme and motto, then the season's goals as planner-style rows with a progress bar and signal. Second tab **Projets** shows projects by priority (this absorbs the old Cockpit screen: keep `/cockpit` as a redirect and update the nav, palette, README and tab bar).
- Goal detail panel (same `?g=` pattern as tasks and projects): the thread as a vertical timeline, linked items with their state, signals, edit and pause. "Ajouter un jalon" and "Ajouter une tâche" create the milestone or task through the S2 write paths and link them.
- **Découper avec Claude**: for a *sans fil* goal, a button that copies a ready-made prompt (goal, measure, context, what to produce) for use in a Claude chat once S9 exists; until then it is the manual breakdown form. No API call to a model from the app.
- Signals appear on Aujourd'hui only when they need attention (a small "Objectifs" section), and in the Sunday revue (S7).
- Markdown export of the vision and goals to `VAULT_GOALS_PATH` when set (a button in Réglages and after each edit): one file for the vision, one per season.

## Done when
- In demo mode: a goal can be created with each measure, linked to projects and tasks, and shows its thread and signal; the fourth active goal in a season is refused with a clear message; the nav and palette use Objectifs.
- Unit tests cover progress for each measure, the signals and the per-season limit. `npm run check` passes.
