# S3 — Blocks and the replan

Goal: the core pain. A block that ends without its task done never dies quietly: it lands in *À replacer* and gets a new slot in one tap, or the rest of the day re-flows. Depends on S2 (priority, effort). Product rules: [SPEC.md](../SPEC.md) (blocks and replanning, priority and effort).

## 1. Data
- `blocks`: id, calendar source id, external event id, start, end, `taskId` (nullable), `status` (`proposed` | `planned` | `done` | `missed` | `replanned` | `dropped`), `origin` (`cockpit` | `calendar`), estimate in minutes, `updatedAt`.
- `task_types`: id, name, `minutesPerPoint` (nullable until learned), `samples`. A task's type comes from its source or tags (config: `taskTypeProp` or a mapping table in Réglages); a task with no type uses `default`.
- `settings` rows for the work window (default Monday to Saturday, 09:00–22:00), the grace period after a block ends (default 10 min) and default block length when a type is unknown (90 min).
- `block_log`: each state change and replan decision (for undo and for learning).

## 2. Calendar reads and writes
- Extend `GOOGLE_SCOPES` with `https://www.googleapis.com/auth/calendar.events`; show a "Reconnecter pour autoriser l'écriture" button in Réglages when the stored token lacks it.
- Calendar roles already exist in source config: `travail` and `perso` calendars hold blocks; `socle` and `cours` are **protected**; `engagement` is **avoided**. Cockpit only ever creates, moves or deletes events on `travail` and `perso` calendars, never on the others (enforce in one function, with a unit test).
- Every event on a `travail` or `perso` calendar is a block (`origin: calendar` when Cockpit did not create it). Link a block to a task through a marker line `cockpit:task=<taskId>` in the event description, or the task identifier in the title (`ENG-12`, matched with the same pattern as capture).
- A block moved by hand in Google Calendar is respected: the next sync updates the block, and Cockpit never moves it back.

## 3. The engine (pure, `src/engine/`, with unit tests)
- `freeSlots(events, window, protectedKinds)`: free intervals inside the work window, after removing protected events and (softly) engagement events.
- `placeTask(task, slots, options)`: best slot this week for a task, in order: due date pressure, priority, contiguity, learned or default duration. Never on Sunday, never over a protected event, never ending after 22:00. Overlapping an `engagement` event is allowed only when the caller passes `allowAvoided: [eventIds]` (the user approved).
- `replanDay(day, blocks, tasks, slots)`: objective: finish every mandatory item on time and keep habits as far as possible. Mandatory = Urgent, or Haute with a due date within 48 h, or a deliverable with a grade. Returns a proposed plan plus a diff (moved, dropped, unplaceable) and the reason for each decision. Unplaceable work is reported, never silently dropped.
- `durationFor(task, types)`: effort points × learned minutes per point, else the type's default, else 90.
- Learning: when a block ends `done`, record actual minutes (block length, or tracked time if present) and update `minutesPerPoint` with an exponential moving average. Ask the user once per new task type for an initial estimate (a small inline question on the first block of that type).
- At least 25 unit tests: protected slots, Sunday, work window edges, avoided events with and without approval, mandatory ordering, overload (more work than time), learning.

## 4. UI
- **Maintenant** strip at the top of Aujourd'hui: current block, linked task, time left, then the next block. Empty state when nothing is planned now.
- **À replacer** card: blocks whose time passed while their task is still open in its source (`done` detection: the linked task is closed in Notion or Linear → block `done`). Ask only in that case.
- **Replan sheet** (bottom sheet on phone, side panel on desktop): options "Laisser Cockpit choisir" (default, selected), "Ce soir", "Demain matin", "Découper en deux", "Abandonner". Each option shows the concrete slot. Confirming writes the event (S3 calendar write) and the log entry.
- **Replanifier ma journée**: runs `replanDay`, shows a before/after list with reasons, and applies only on confirmation.
- Block-end reminder in the app while it is open (banner at block end + grace). Push notifications arrive in S4; until then add a Google Calendar reminder to events Cockpit creates.
- Task detail panel: "Planifier un bloc" with "Laisser Cockpit choisir" and a manual time picker.
- A basic week view at `/semaine` (read-only list of blocks per day) is enough here; the planning UI comes in S7.

## 5. Demo and tests
- `src/db/demo.ts` adds blocks (done, missed, planned, one unlinked), task types and a day with a clash. In demo mode, calendar writes only change local `blocks` and events tables.

## Done when
- In demo mode: a missed block appears in À replacer; the replan sheet offers real slots; confirming moves the block and logs it; "Replanifier ma journée" shows a before/after and applies it; the protected, Sunday and work-window rules hold in unit tests.
- `npm run check` passes.
